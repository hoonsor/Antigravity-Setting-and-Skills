# #分支接手：交接文件範本

所有文件放在 worktree 的 `.handoff/` 內，一律繁體中文（台灣用語）。**寫給「完全沒看過這段對話、也不認識使用者」的另一個 AI**：凡是需要它猜的地方都要寫清楚。具體優先於抽象：寫檔名、函式名、指令、錯誤訊息原文，不寫「做了一些優化」。

## 2. FEATURES.md（功能矩陣；#分支比較 會直接解析這個表）

格式必須保持：每列一個功能、第一欄是 `F` + 兩位數編號、第三欄是狀態符號。

```markdown
# 功能清單與狀態

狀態：✅ 完成並驗證｜🟡 部分完成／未驗證｜⬜ 未開始｜❌ 放棄（備註寫原因）
規則：不要重新編號或刪列；新增功能用下一個編號，備註標 🆕；每次工作結束更新本表。

| ID | 功能 | 狀態 | 驗收標準 | 相關檔案 | 備註 |
|----|------|------|----------|----------|------|
| F01 | 使用者登入 | ✅ | 正確帳密可登入、錯誤顯示提示 | src/auth/login.ts | |
| F02 | 匯出 Excel | 🟡 | 匯出檔可在 Excel 開啟且欄位正確 | src/export/xlsx.py | 中文欄名亂碼未修 |
| F03 | 排程寄信 | ⬜ | 每天 08:00 寄出摘要 | | |
```

驗收標準要可客觀判斷，讓不同 AI 的成果能用同一把尺比較。
